# Компания, филиалы и точки обслуживания

Теперь это три самостоятельных уровня: **Company → CompanyBranch → Branch**. В коде Branch по совместимости означает точку, а CompanyBranch - её филиал. Филиал может содержать несколько точек: этажи, корпуса, зоны или отдельные направления. У другой компании и другого филиала - свои точки.

## Создание

1. Компания: «Организация → Филиалы → Добавить филиал». Название, код (уникален в компании), адрес и активность.
2. В строке филиала нажать «Точки обслуживания», затем «Добавить точку». В форме выбран филиал. Указать название, код, адрес/этаж, рабочие часы и активность.
3. Повторить создание точек в этом филиале. Создать следующий филиал и его набор точек. Ограничения «только два этажа» нет.
4. В верхней панели выбрать филиал, затем точку. Второй список содержит только доступные точки выбранного филиала. Пустой филиал появится в рабочем переключателе после добавления первой точки.
5. Услуги, подуслуги, сотрудники, коды регистрации и устройства настраиваются в конкретной точке. В назначениях и регистрации отображается «Филиал / Точка».

В Control Plane также есть отдельные разделы «Филиалы» и «Точки обслуживания». Установке и токену назначаются конкретные точки. Подписанный пакет передаёт только необходимые филиалы и их точки. Локально созданные филиалы/точки автоматически в Control Plane не выгружаются; используйте локальные коды или заранее создайте структуру в Control Plane и примените подписанный пакет.

## Изоляция и права

Каждая точка имеет отдельные услуги, очередь, вызовы, смены, передачи, нумерацию и комнату Socket.IO. Устройство закреплено за одной точкой. Другую точку нельзя выбрать заголовком запроса или подменой serviceId. Общая компания или филиал не объединяет очереди автоматически.

Администратор компании видит все филиалы и точки своей компании. Администратор точек и сотрудник получают явный доступ к точкам. Назначение на точку не даёт доступа к её соседям в том же филиале. Новая точка не расширяет права существующих сотрудников автоматически. Управление филиалами доступно администратору компании.

Код точки уникален внутри филиала, поэтому P1 в CENTRAL и P1 в NORTH допустимы. В CSV/XLSX используйте companyBranchCode (код филиала) вместе с branchCode (код точки), если коды повторяются. Неоднозначный код без филиала отклоняется. Для услуг по-прежнему используются префиксы и наследование подуслуг.

Отчёт фильтруется по филиалу и точке. Сводка филиала включает только доступные пользователю точки. Для фильтра конкретной услуги выберите её точку в верхнем переключателе.

## Существующие данные

Новые миграции обеих баз создают филиал для каждой прежней точки/филиала, копируя её имя, код и адрес. Прежняя запись остаётся его точкой с тем же ID. Талоны, устройства, сессии, регистрации, сотрудники и назначения не удаляются и не перенумеровываются. Названия старой точки и нового филиала могут совпадать; точку можно переименовать без сброса подключения.

Филиал существующей точки менять нельзя. При необходимости создайте новую точку; история останется в старой. Выключение филиала закрывает доступ к его точкам, но перед этим требуется закрыть смены. Администратор компании может восстановить активность.

Протокол Runtime v2 сохраняется: branchId/branchIds - прежние ID точек, companyBranchId - новый ID филиала. Добавлены companyBranch/companyBranches в снимке, сущность /api/admin/company-branches и фильтр companyBranchId в отчётах. Старые подписанные активации без списка филиалов обрабатываются по совместимости. Чужую компанию нельзя назначить ни в API, ни через FK базы.
