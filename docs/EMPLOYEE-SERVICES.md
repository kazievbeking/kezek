# Работа по услугам сотрудника, без столов

Runtime 1.1.0 использует прямые назначения услуг сотрудникам. Столы убраны из меню, выбора смены, устройств и отчётов.

В админке открыть «Организация → Услуги», затем «Персонал → Сотрудники». Назначить сотруднику филиалы и услуги. Родительская услуга включает потомков, конкретная подуслуга не разрешает соседние ветки. Пустой список услуг не даёт права начать смену или вызвать клиента. В рабочем месте сотрудник видит назначенное дерево и начинает смену без выбора стола.

FIFO выбирает самого раннего ожидающего только по разрешённым услугам выбранного филиала. Несколько сотрудников могут обслуживать одну услугу: один талон не вызывается дважды. Сотрудник ведёт одну смену и одного активного клиента. Передача разрешена свободному работающему сотруднику того же филиала с нужным назначением; права повторно проверяются при принятии. Номер и интервалы участия сохраняются.

На дисплее: «номер талона → имя сотрудника». Публичное имя — единственное новое персональное поле назначения; логины, email и полный список сотрудников не передаются устройству. Control Plane не получает списков сотрудников.

CSV/XLSX: firstName, lastName, login, email, role, branchCode, services. Префиксы услуг — через `|`. Старая лишняя колонка desks игнорируется. Отчёты используют сотрудников, услуги, филиалы и время.

## Сохранность данных

Таблица Desk и исторические ссылки в талонах, сменах, вызовах и интервалах не удаляются. Для прежних пользователей с пустым serviceIds копируются услуги ранее назначенных столов в разрешённых филиалах. Явные назначения сохраняются. Если назначений не было, доступ ко всем услугам не выдаётся. Открытые смены и активные талоны можно завершить. Новые операции не требуют deskId. Создание/изменение столов через API отключено с 410.

## Протокол

Изменение явно версионировано: **Runtime HTTP/Socket.IO — protocol=2**, Control Plane остаётся на protocol=1. Frontend каждой части отправляет свою версию. Явный X-Kezek-Protocol:1 на Runtime получает 426 до исполнения команды; без заголовка используется текущая версия. После внедрения обновить старые страницы. Receipts команд и история сохранены.

Health Runtime: version=1.1.0, protocol=2, model=employee-services. Новые вызовы содержат userId и destination; deskId/deskNumber равны null. В публичном снимке дисплея userId исключается. Старые nullable поля и архивные фильтры сохраняют историю. Подписанные активации/отзывы совместимы, новые manifests Runtime требуют protocol=2. Переход через автоматический updater нужно репетировать в staging; его применение в демонстрации выключено.
