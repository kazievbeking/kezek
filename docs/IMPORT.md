# Добавление и массовый импорт сотрудников

Runtime 1.1.0: столы отменены. Назначения задаются только в services (префиксы услуг/подуслуг через `|`). Актуальный шаблон не содержит desks; старая лишняя колонка игнорируется. Пустое назначение не даёт права начать смену. См. EMPLOYEE-SERVICES.md; прежние упоминания столов ниже описывают старую модель.

## Редактирование

В админке выберите филиал → «Сотрудники». Доступны форма создания/редактирования, назначения, блокировка, сброс пароля и редактирование основных полей таблицей. У каждой записи отдельный логин. Администратор филиала не может редактировать более высокую роль или пользователя с назначениями за пределами своей области. Изменение активных назначений требует закрытой смены; блокировка немедленно удаляет сессии.

## CSV/XLSX

Вкладка «Импорт сотрудников»:

1. Скачать CSV-шаблон или использовать `templates/employees.csv`.
2. Загрузить UTF-8 CSV (`;` или `,`) либо XLSX. Лимит 5 МБ, 200 строк данных, 30 столбцов. Архив XLSX проверяется до чтения: размер распаковки до 30 МБ, число записей и фактическая bounded-decompression каждого файла; зашифрованные/ZIP64-файлы не поддерживаются.
3. Сопоставить столбцы. Названия входных колонок могут быть любыми: сопоставление явное. `firstName`, `lastName`, `login`, `email`, `role`, `branchCode`, `desks`, `services` автоматически распознаются.
4. Выбрать обработку существующего логина: ошибка, пропуск, обновление.
5. Выполнить preview. У каждой строки — номер, статус, ошибки. Некорректная строка не создаёт пользователя.
6. Подтвердить импорт **проверенных** строк. Система заново проверяет права и дубликаты в транзакции. При новом конфликте весь commit откатывается; следует повторить preview.
7. Получить отчёт и сохранить индивидуальные временные пароли. Они показываются только в ответе commit и не сохраняются в истории импорта. При обновлении существующего пользователя пароль не меняется; сброс — отдельное действие.

`role` — COMPANY_ADMIN, BRANCH_ADMIN или STAFF. `branchCode` — один либо несколько кодов через `|`. `desks` — номера столов через `|`; `services` — префиксы услуг через `|`. Назначения разрешены только внутри указанных и доступных филиалов. Если номер стола/префикс встречается в нескольких выбранных филиалах, назначаются подходящие записи каждого выбранного филиала. Для точного контроля выбирайте один филиал в строке или редактируйте назначения формой.

Email необязателен. Пароли сотрудникам не задаются одним общим постоянным значением: для каждой новой записи генерируется собственный случайный пароль, хешируется Argon2id и включается обязательная смена при первом входе. В режиме без email передайте пароль сотруднику разрешённым внутренним способом. JSON экспорта учётных данных содержит секреты — хранить и удалить после передачи согласно правилам заказчика.

Задание preview принадлежит создавшему его администратору. Другой пользователь не может подтвердить его по ID. После commit задание закрыто. Если ответ с временными паролями был потерян, проверьте наличие записей и выполните индивидуальный сброс — не создавайте дубликаты и не публикуйте пароли в журналах.
