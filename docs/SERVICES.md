# Услуги и вложенные подуслуги

Актуально для Runtime 1.1.0: столы отменены. Услуги и подуслуги назначаются непосредственно сотрудникам; пустое назначение не даёт права обслуживать. Инструкция — EMPLOYEE-SERVICES.md. Упоминания столов ниже описывают прежнюю модель и её историю.

В админке компании открыть «Организация» → «Услуги». Список отображается деревом. Кнопка «Добавить подуслугу» создаёт элемент внутри выбранной услуги. В обычной форме добавления/редактирования поле «Родительская услуга» позволяет выбрать существующий раздел; «Без родительской услуги» возвращает элемент на верхний уровень. Вложенность поддерживает несколько последовательных уровней.

Каждый элемент имеет локализованные названия RU/KK/EN, свой уникальный в филиале префикс и переключатель активности. Префикс родительского раздела сохраняется, но новые талоны для раздела с подуслугами не выдаются. На терминале посетитель сначала выбирает разделы, затем конечную услугу. Только выбор конечной услуги создаёт талон. Есть путь навигации и возврат назад; в результате и на чеке отображается полный путь услуги.

Добавление подуслуг к прежней услуге превращает её в раздел для новых посетителей. Уже выданные талоны сохраняют serviceId, номер и историю; их можно обслужить по прежним назначениям. Отключение раздела скрывает всю его ветку на терминале и запрещает выдачу через API. Уже ожидающие талоны отключённой ветки сохраняются и могут быть обслужены. Если все подуслуги отключены, раздел не превращается обратно в выдаваемую услугу: терминал показывает пустой раздел.

Назначение родительской услуги столу включает её потомков. Ограничение сотрудника проверяется независимо: разрешены только пересекающиеся ветки стола и сотрудника. Пустой список услуг сотрудника, как раньше, означает отсутствие дополнительного ограничения поверх стола. Можно назначить конкретную подуслугу, чтобы исключить соседние ветки. Проверки действуют при вызове следующего, запросе и принятии передачи. В списках назначения показывается полный путь. CSV/XLSX использует прежние уникальные префиксы; префикс родительского раздела также охватывает его потомков.

Фильтр услуги в отчёте включает выбранную услугу и её потомков. Группировка использует текущее дерево на момент отчёта; перенос подуслуги меняет её принадлежность к ветке в последующих выборках, не переписывая талоны. Время, интервалы и итоги считаются по прежним формулам.

Все связи ограничены одной компанией и одним филиалом. Выбор самого себя или своего потомка в качестве родителя запрещён в API и PostgreSQL. Миграция добавляет nullable parentId и защитные ограничения, существующие услуги остаются на верхнем уровне. Протокол v1 сохраняется: новое поле добавлено, прежние поля и команды остаются прежними.
