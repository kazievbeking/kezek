# Kezek: развитие веб-платформы

- Сначала изучать существующие модули и docs/STATUS.md. Сохранять работающие функции и данные.
- Расширять модули, разделять backend/frontend, API, бизнес-логику и стили. Не переписывать весь проект без причины.
- PostgreSQL — источник истины. Изменять схему новыми миграциями, не редактировать применённые.
- Control Plane и Runtime имеют независимые backend и базы. Повседневная работа Runtime не зависит от Control Plane, GitHub или интернета.
- Проверять companyId, branchId, роль и действие в HTTP, сокетах и БД; пользователь может иметь несколько разрешённых филиалов.
- Очередь менять транзакционно с идемпотентностью и outbox. Не объединять независимые локальные очереди.
- Сохранять polling как рабочий транспорт и резерв для WebSocket; поддерживать cloud и local.
- Поддерживать ru/kk/en, словари и локализованные настраиваемые значения.
- Не отправлять персональные данные из изолированной установки. Секреты не передавать в telemetry и логи.
- Обновления подписывать и проверять локально; приватный ключ Control Plane не размещать у заказчика.
- Обновлять документацию, критические тесты и docs/STATUS.md. Не выдавать заглушки/непроверенное за готовые функции.
- Не коммитить .env, ключи, пароли, токены и backup. Не добавлять APK, EXE, Electron, оплату, SMS и запись без отдельного задания.
